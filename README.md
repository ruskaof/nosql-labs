# EventHub - NoSQL Database Project

[![EventHub](https://github.com/ruskaof/nosql-labs/actions/workflows/eventhub.yml/badge.svg)](https://github.com/ruskaof/nosql-labs/actions/workflows/eventhub.yml)

## Обзор

REST API для управления мероприятиями с многоуровневым хранением данных:

| Хранилище | Назначение |
|-----------|-----------|
| **MongoDB** | Основное хранилище пользователей и мероприятий (шардированный кластер) |
| **Redis** | Сессии, кэш реакций, кэш отзывов, кэш рекомендаций |
| **Cassandra** | Реакции (лайки/дизлайки) и отзывы |
| **Neo4j** | Граф для рекомендаций мероприятий (коллаборативная фильтрация) |

## API

Аутентификация — cookie `X-Session-Id`. Авторизованные эндпоинты возвращают `401`, если cookie отсутствует или сессия не привязана к пользователю.

### Сессии

| Метод | Путь | Описание |
|-------|------|----------|
| `POST` | `/session` | Создать / обновить анонимную сессию |

### Аутентификация

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| `POST` | `/auth/login` | нет | Войти (привязать пользователя к сессии) |
| `POST` | `/auth/logout` | нет | Выйти (удалить сессию) |

### Пользователи

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| `POST` | `/users` | нет | Зарегистрироваться |
| `GET` | `/users` | нет | Список пользователей (`name`, `id`, `limit`, `offset`) |
| `GET` | `/users/{id}` | нет | Профиль пользователя |
| `GET` | `/users/{id}/events` | нет | Мероприятия пользователя |

### Мероприятия

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| `POST` | `/events` | **да** | Создать мероприятие |
| `GET` | `/events` | нет | Список мероприятий (`title`, `id`, `category`, `city`, `price_from`, `price_to`, `date_from`, `date_to`, `limit`, `offset`, `include`) |
| `GET` | `/events/{id}` | нет | Мероприятие по ID (`include=reactions,reviews`) |
| `PATCH` | `/events/{id}` | **да** | Обновить категорию / цену / город (только организатор) |

Допустимые значения `category`: `meetup`, `concert`, `exhibition`, `party`, `other`.

`include` — список через запятую: `reactions`, `reviews`.

### Реакции

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| `POST` | `/events/{id}/like` | **да** | Поставить лайк |
| `POST` | `/events/{id}/dislike` | **да** | Поставить дизлайк |

### Отзывы

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| `POST` | `/events/{id}/reviews` | **да** | Создать отзыв (`rating` 1–5, `comment` до 300 символов) |
| `GET` | `/events/{id}/reviews` | нет | Список отзывов (`limit`, `offset`) |
| `PATCH` | `/events/{id}/reviews/{rid}` | **да** | Обновить свой отзыв |

### Рекомендации

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| `GET` | `/recommendations` | **да** | Рекомендованные мероприятия на основе лайков |

Рекомендации строятся по алгоритму коллаборативной фильтрации (Neo4j) и кэшируются в Redis по принципу Cache-Aside с TTL. Возвращает мероприятия, отсортированные по релевантности, дедуплицированные по названию (при совпадении — ближайшая дата начала).

### Системные

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/health` | Проверка работоспособности |
